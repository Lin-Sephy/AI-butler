# D 视角：番茄 todo 忠实用户能不能迁过来再不回去

> 2026-04-22 小克 review
>
> 视角定义：一个把番茄 todo 当每日工具用了好几年的老用户。她打开我们的产品是来**试用**的——几天之内能让她"这个更好用，我不回去了"就留下，否则回流。
>
> 这一视角的核心判断：**差异化要够香 + 基础能力不能比竞品差**。如果差异化不够香，用户不会来；如果基础能力比番茄 todo 差，用户来了也会跑。

---

## 先理解这类用户的心理锚点

番茄 todo 老用户对下列体验有"**成瘾式**"依赖。这些不是"功能"，是她每天的操作记忆：

1. **番茄自动循环**：25 专注 → 5 休息 → 25 专注 → 15 长休。不需要思考，跟着节奏走。
2. **白噪音陪伴**：打开 app = 打开雨声 / 咖啡馆 / 图书馆 / 自然声，是**专注状态的锚**。
3. **数据可视化**：每天看今天几个番茄，每周看趋势，年底看"今年专注了 XXX 小时"。数据是**成就感回路**。
4. **连续打卡 / 累计番茄**：连续 200 天不断卡的成就感——一断了就塌方。
5. **快速开始**："就先专注 25 分钟什么都行"的入口。不用建任务、不用想做什么。
6. **专注结束提示**：番茄归零的"叮"一声 / 推送通知，是**一次专注闭环的仪式**。

**这六条里当前我们一条都没完整做到**。下面按"先看基础能力守得住不，再看差异化能不能反杀"两层来审。

## 第一层：基础能力守得住吗（番茄 todo 用户不会为之惊艳，但缺了就会回流）



### 🔥 D-1. 没有白噪音(暂时延后)

**代码现状**：`FocusOverlay.jsx:126` 写"🎧 白噪音（待接入）"占位。C 视角已经提到"待接入"是 bug——D 视角加码：**白噪音对番茄 todo 用户不是 nice-to-have，是核心功能**。

**番茄 todo 用户预期**：开始专注时默认播放上次用的白噪音；可切换雨 / 咖啡馆 / 图书馆 / 篝火 / 海浪。

**技术实现并不难**：HTML5 `<audio loop>` + 3-5 个公共音源（Free Sound / Zapsplat 有免费可商用）。web 端不涉及权限。大概 1-2h 能做出最简版本。

**小克倾向**：
- 先上 3 个：**雨声 / 篝火 / 林间** —— 选这三个能呼应"松针雪地小白鼬"调性
- 音量控件 + 静音开关 + 上次选择落 localStorage
- 建议音源不用 AI 生成，找真实录音，调性差距很大

**优先级**：**最高**。是每日体感的锚。

- 本周：7 天折线或柱状图
- 累计：总番茄数 / 总时长 / 连续打卡天数

**2026-04-23 定稿方案**（Sephy 和小克多轮 review 后的 ground truth）：

**设计稿**：`docs/references/白鼬/数据页设计稿-v2.html`（双击浏览器打开看完整 mockup，含 mock 数据和全部交互。做 React 组件时以它为视觉和交互的 ground truth）

**页面结构（4 个 section，顺序不要变）**：

1. **HERO · 今日**
   - 大字今日总专注时长（`2h 15min` 级别，IBM Plex Serif 300 weight，88px）
   - 右侧两项：今日任务数 + 最常做的事（胶囊 tag）
   - 布局 `flex justify-content: flex-start`，整体靠左（不居中，不撕开左右）

2. **任务分布 · 环形图**
   - 带日/周/月 tab 切换（放在 section-head 右侧）
   - 环形图**整块居中**（viewBox 240×160，圆心 120,80）
   - 中间显示总时长（**小字 10px SVG 字号**，不要"本周总时长"这种后缀说明）
   - 5 段 callout **引线拉出**"任务名+时长"，**不用右侧 legend 列表**
   - callout 起点是环外 r=50 位置，先短线向外再水平到 label

3. **我的专注时段**（**拆两个子图**）
   - **上：一天里什么时候**（24h 分布）
     - 横轴 0-23 点，每根柱子 = 该时段累计分钟（来自最近 30 天聚合）
     - 横向可拖动滚动（手机端塞不下 24 根）
     - 最高那根 `--color-primary` 深蓝标识"高峰"
     - meta 文字显示"高峰在 HH:00-HH:00"
     - 默认滚动定位到 25% 位置（白天起）
   - 中间细分隔线 `.sub-divider`
   - **下：这个月每一天**（30 天每日趋势）
     - 横轴 1-30 号，柱高 = 当日总专注分钟
     - 今天那根 primary 深蓝
     - 未来的日子柱子为空 + tooltip 显示"还没到"
     - 默认滚到最右看到今天
     - meta 显示"今日 N min"

4. **累计 · 松林**
   - SVG 松林 · **feTurbulence + feDisplacementMap filter** 把三角形边扰动成针叶质感
   - 三层空间雾化：前景清晰 / 中景 needle-mid filter / 远景 feGaussianBlur
   - 冷蓝调 `#4896c4`，**不要绿色**（design-tokens 刻意放弃绿色）
   - **小白不出现**在这一页
   - 每棵树独立 `<g id="tree-N">` 分组，按累计打卡天数控制显示棵数
   - 按**累计**打卡不按连续（断卡不塌房，避免心理压力——Sephy 的 `user_sephy_cycles` 钉的"没自带停止键+焦虑底色"决定了这条）
   - 左：累计大字 + "已陪伴你 X 小时"
   - 右：小字 caption"每一天的专注，都让林子长出一棵"
   - **档位定稿（2026-04-23）**：两阶段叙事——
     - 1-10 天：前景+中景依次种出 10 棵（1:1 映射，和 caption 一致）
     - 11-30 天：前景 10 棵满员后，**远景层 9 棵的 opacity 从 0.55 线性升到 1.0**，雾慢慢散开林子"变深"
     - 30+ 天：远景 1.0 稳态，不再变化（不鼓励上瘾型打卡，到此为止）

**三条核心原则**：
- **小白不在数据页**（砍了 v1 计划里的白鼬插画）
- **不做 DS 叙事文案**（砍了 v1 反杀 1；用户已在聊天里自然听 DS 聊数据，见 memory `feedback_ds_behavior_data.md`）

### 🔥 D-4. 没有"专注结束提示"

**代码现状**：`FocusOverlay.jsx:21` 倒计时归零只是 `onComplete(task.id)`，没声音、没通知、没视觉提醒。

**番茄 todo 用户预期**：番茄归零 → 声音提示（钟声 / 柔和叮 / 自定义）+ 浏览器通知（如果用户授权）+ 视觉反馈（闪烁 / 过渡动画）。

**特别重要的场景**：用户专注中切到别的 tab（比如看参考资料），番茄结束她根本不知道。没有提示 = 番茄白跑。

**小克倾向**：
- 结束时播一个短音效（1-2 秒钟声或小白"喵"一声——调性上走后者）
- 请求 `Notification.permission`，授权后用 Web Notification API 推"小白：25 分钟到啦"
- 视觉上：计时器 `00:00` 后维持屏幕 1-2 秒，给小白一个"小跳"或"冒爱心"的微动画，再切下一阶段

**工作量**：2-3h。

**优先级**：**高**。配合 D-1 才算一个完整番茄闭环。

### 💡 D-6. 没有通知 / 提醒

番茄 todo 有每日提醒（"晚上 9 点了，今天的番茄还没做完呢"）。Web app 能用 Web Push 做类似的，但需要后台 Service Worker + 服务端推送机制——**工作量大**。

**小克倾向**：**暂不做**。Web Push 链路太长，维护成本高；且用户通常把 app 打开着，声音+Web Notification（前台）已经覆盖 80% 场景。等 PWA 完善度上去再说。

**优先级**：**低**。不是迁移拦路石。

## 第二层：差异化反杀（番茄 todo 永远做不到的事）

如果只补上第一层，用户会留下但没惊艳。真正"再也回不去"的是：**用小白 / AI 陪伴的调性重新做番茄 todo 的核心交互**。

这部分不是代码 bug，是产品设计机会。D 视角提出来，但**不写具体代码方案**——需要 Sephy 做产品决定。



### 💎 反杀 2：番茄结束不是"叮"一声而是小白探头

番茄 todo 的结束提示是功能性的（声音 + 通知弹窗）。**我们可以做仪式感**。

场景：`00:00` → 白鼬从遮罩右下角角落蹦出来 → 嘴里叼着一根松针（或戴着小耳机）→ 气泡说"到啦～休息 5 分钟，喝点水"。

**这种小动画就是你把 Clawd 研究搞明白的原因**——不是一模一样，但结构一样（pixel art 角色 + 状态机）。

### 💎 反杀 3：连续打卡不是火焰而是"松针林"

番茄 todo 用"🔥 连续 N 天"做成就感。

**我们可以用**：白鼬的松针林背景——连续打卡 7 天 = 林里多 3 棵松针，30 天 = 下雪了，100 天 = 林子成密林。**打卡数据和产品视觉直接绑定**，断了卡，就不长树。

（这和 project_progress.md 里写的"松针雪地"主视觉呼应——让这个 motif 承担更多叙事功能。）

## 三、D 视角优先级建议

要让"番茄 todo 用户试用 → 留下"路径通，**四件必做**（按烫度）：

1. **D-1 番茄自动循环**（3-4h，最大单点瓶颈）
2. **D-3 数据页做出来**（先做最简版，2-3h）—— 配 💎 反杀 1 的文案用 DS 生成
3. **D-2 白噪音**（1-2h）—— 配 💎 反杀 4 调性
4. **D-4 专注结束提示**（2-3h）—— 配 💎 反杀 2 小白探头

这四件合起来大约 **10-12h**，做完可以说"基础不退步"。

**然后是差异化反杀**（护城河，Sephy 决定要不要做）：

5. 💎 连续打卡 → 松针林视觉（配桌宠第 3 步做）
6. 💎 AI 主动关怀（打开时触发机制）

## 四、D 视角没提、为什么


- **任务和番茄的多对一关系**（一个任务做 N 个番茄）—— 是产品范式差异，要 Sephy 决定要不要改。**不是代码 bug**。
- **Web Push 通知**（D-6）—— 工作量大回报中，不值得现在做。
- **锁机 / 强制专注** —— Web app 做不了完整锁机，能做的也只是 visibilitychange 警示——已经在 C 视角顺手提过。

## 五、D 视角最核心的一句话

**不要直接抄番茄 todo**。产品真正的护城河是小白、是白鼬、是漫画气泡、是 AI 记忆。

如果花 50h 去抄一个番茄 todo 的柱状图、锁机、社区——我们会做出一个"有 AI 的差劲番茄 todo"。番茄 todo 核心功能背后有巨大的产品投入积累，追不上也没必要追。

**正确路径**：
- 第一层（基础能力）**补到 80 分就行**，够用、不退步即可
- 第二层（差异化反杀）**做到 120 分**，让番茄 todo 永远做不了

这样番茄 todo 用户试用几天后会这样想："这里的基础功能够我用，而且**我好像离不开那只白鼬了**"。

这才是"再也回不去"的机制。
