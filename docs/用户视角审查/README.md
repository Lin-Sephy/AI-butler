# 用户视角审查

2026-04-22 Sephy 让小克从"用户角度"过一遍源代码，看还有什么功能需要改进和优化。

**分四层视角，一层一文档：**

| 视角 | 定义 | 文件 | 状态 |
|---|---|---|---|
| A | 陌生新用户——第一次打开 app、没填 profile、没跟小白说过话 | `A-陌生新用户.md` | ✅ 审完 + 5 件全落地 |
| B | Sephy 自己这种高频老用户——已有 memory、persona、任务堆、BYOK 配好 | `B-高频老用户.md` | ✅ 审完 + 5/6 件落地（B-6 不做）|
| C | AI 交互设计师同行——盯交互一致性 / 状态反馈 / 空态 / 错误态 | `C-交互设计视角.md` | ⏳ |
| D | 番茄 todo 忠实用户——能不能迁过来并且再也回不去 | `D-番茄todo迁移者视角.md` | ⏳ |

**测试指引**：A/B 视角改动后 Sephy 自己手工验证用 → `手工测试指引.md`。每份视角文档顶部有 "✅ 执行记录" 段落，记下实际落地的 commit 和文件。

**一条原则**：每层只挑"真烫"的，不做百条清单。四层暴露的问题不重叠，对应四条不同的产品底线——
- A：打开立刻开始
- B：陪伴积累关系
- C：我不要粗制滥造
- D：差异化要够硬 + 基础能力不能比竞品差

**配套的协调文档**：多 agent 并行推进时的分工和顺序见 `分工与推进顺序.md`。每个 agent 开工前先读这份 + 对应视角文档。

**记录口径**：每个问题至少带「代码位置 / 现象 / 根因 / 小克倾向」。代码位置用 `path:line` 方便后续小克导航。
