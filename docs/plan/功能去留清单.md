## 核心发现（审前先看）

1. **后端 FastAPI 已经建好 28+ 个 endpoints**，所有 Streamlit 逻辑都镜像到 API 里了。前端重写主要是"换壳"，不是重造业务。
2. **唯一结构性改造**：所有 endpoint 加 `user_id` 过滤 + Supabase RLS（多用户必须）。
3. **聊天→任务的数据耦合已经在 API 层解耦**：`POST /api/chat` 返回 signal 和 task 建议，`POST /api/task/record` 独立写任务。v2 前端只需要组装这两步。

## C. 改形态（业务保留，UI 结构变）

### C1. Streamlit 左侧 << 抽屉 → v2 的"四 tab 分布"（2026-04-15 重写）

Streamlit 把所有功能塞左侧抽屉。v2 四页结构下**按场景就近原则**而非"使用频率"拆分——配置项靠近它影响的功能，使用动线不绕。

**任务页顶部栏（高频常看）：**
- 当前精力档位 + 手动调整入口
- 今日任务统计（小字："执行中 1 / 待完成 3 / 已完成 2"）

**任务页内（任务相关配置）：**
- 循环任务管理（添加 / 删除）—— 跟今日任务列表在同一场景

**聊天页右上角 ⚙️（聊天相关偏好）：**
- 小白人格选择（INFP/INTJ/INTP）
- 自粘贴性格
- 小白命名
- 用户手记编辑
- AI 自动记忆查看 + 清空
- **API key**（与"我的"页共享同一份配置）

**"我的" tab（账号 + 产品级）：**
- 账号 / 邮箱绑定（多用户新增）
- **API key**（与聊天页 ⚙️ 共享同一份配置——双入口，单一真源）
- 关于 / 版本

**API key 双入口的理由：** 既是聊天能不能跑的硬条件（→ 聊天 ⚙️），也是账号身份组件（→ 我的）。两边都让用户找到，但底层是同一份 user_profile.api_key 记录。

## F. #4 数据耦合答案（顺带解决）

### 聊天推任务 → 任务页的完整数据链路

```
[用户在聊天页输入]
  ↓
POST /api/chat { message, session_id }
  ↓ 后端调用 call_chat()
← 返回 { reply, signal, task_response? }
  ↓ 前端解析
  ├─ signal 说"触发任务" + task_response 有内容 → 消息气泡下显示"记录 / 再聊聊"按钮
  └─ 否则 → 普通消息，无按钮

[用户点"记录"]
  ↓
POST /api/task/record { keyword, type, minutes, detail }
  ↓
← 返回 { task_id, status: "idle" }
  ↓ 前端两件事并行：
  ├─ 聊天气泡更新为"已记录「xxx」～"
  └─ 全局 state 的任务列表 append 新任务（Tab 切到任务页立即看到）
```

### 跨页面状态同步方案

- **全局 state**：React Context 或 Zustand
- **关键 state**：`tasks[]`（今日任务）、`currentEnergy`、`activeTask`、`aiMemo`、`userProfile`
- **更新时机**：
  - 聊天页"记录"成功 → 直接 push 到 tasks[]，不重新 fetch
  - 任务页进入或 pull-to-refresh → 重新 fetch `/api/tasks/today`
  - 精力手动调整 → 更新 currentEnergy
- **避免的坑**：Streamlit `st.rerun()` 全页刷新的习惯不能带到 React，否则体验会卡

> **2026-04-22 实现状态：** 🟡 **部分完成**。
> - 旧链路（ChatContext.record → 单条推任务 → TasksPage 切 tab 刷）已被 v5 P2 架构替换。现在是：聊天页 DS 调 `create_tasks` 工具 → 后端返 `created_tasks` → `ChatContext.lastCreatedTasks` 暴露给 `PlanConfirmModal` 弹窗让用户事后编辑（改名 / 改时长 / 删）。弹窗内的修改直接走各自独立端点持久化。
> - **TasksPage 主动刷新仍未做**：用户切 tab 过去才 fetch。apiFetch 加了 GET 自动重试（2 次 × 500ms）后偶发 Failed to fetch 大幅缓解，但"聊天页删了任务 → 不切 tab 也能看到任务页变化"的主动广播仍是 TODO。
> - **TasksContext 也没建**：单点用 `ChatContext.lastCreatedTasks` 够用。如果以后真要在聊天页实时显示任务栏变化再建。
