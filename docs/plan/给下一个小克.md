## v5 核心约束（进前端必读）

### 1. MBTI 不是独立字段

v4 时代 persona 是独立枚举（infp/intj/intp），v5 改了：MBTI 只是 `custom_persona` 的**预设模板**。前端按钮用"预设 1/2/3 + 摘要词"展示避免身份标签骗人。点按钮就是把对应文字填进 textarea。数据库和后端只存 `custom_persona` 一个字段。ChatRequest 里没有 persona 字段。

### 2. daily_routine 是纯文本，不是结构化

不要搞时间选择器 / 拖拽等花活。就是一段多行文本，用户自己写。DS 在任务模式下通过 `query_schedule` 工具读。

### 3. 精力系统 v5.0 砍了

不要做精力档位选择、偏差检测、快捷确认按钮等任何精力 UI。energy_log 表保留只为旧端点，energy_level 在新流程里固定 3 占位。

### 4. 设计风格 follow 现有

- 圆角走 `var(--radius)` 等，不写 px
- 颜色走 `var(--color-*)`，不写 hex
- 不用斜体（memory `feedback_no_italic.md` 钉死）
- 图标按钮不加文字标签（memory `feedback_icon_no_label.md` 钉死；aria-label 只给屏幕阅读器，不显 UI 上）
- modal padding 28px（NewTaskModal 的规矩，SettingsPanel/PlanConfirmModal 都照这个）
- 按钮 gap 8，chip 用 accent-soft + accent border
- 所有 confirm 走 `useConfirm()` hook（`contexts/ConfirmContext.jsx`），**不用 window.confirm**

### 5. 验证走后端

max_length 从 API 返回值读，前端不要 hardcode 数字。后端返 400 + 错误文案，前端展示就行。

### 6. 任务模式下 DS 直接动任务栏（v5 架构）

任务相关的动作（删/建/查）都通过 function calling 工具（`core/plan_tools.py`）由 DS 直接动数据库。前端**不要**写 v4 那种"识别任务意图 → 弹记录按钮 → 用户点击 → POST /api/task/record"的前端推荐逻辑——这已经在 v5 退役。前端接的是 `ChatContext.lastCreatedTasks`（DS 本轮通过 create_tasks 写入的任务）+ `planConfirmed`（DS 判定定稿的 judgment 信号），弹 `PlanConfirmModal` 让用户对已落库的数据做事后编辑。

### 7. 错误文案走归一化（2026-04-23 新）

`lib/api.js` 的 apiFetch 会把错误归一化：技术细节 → `console.error`，UI 看到的 `e.message` → 友好文案（"网络有点慢" / "登录失效了" 等）。调用方 `alert(e.message)` 不再暴露 API 路径给用户。要调 bug 打开 F12 Console 看结构化日志：`[api] POST /... → 500 {...}`

## 有漂移风险的（没明文化的潜规则）

- chip 用 `accent-soft + accent border`（时长选中态/idle 都走这个）；scheduled 用 `primary-soft + primary border`
- 按钮间距 gap 8
- modal padding `28px 24px`（NewTaskModal / SettingsPanel / PlanConfirmModal 都是）
- modal maxWidth 420-520（NewTaskModal 420 / SettingsPanel 480 / PlanConfirmModal 520 / ConfirmDialog 360）
- inline style 而不是 CSS module（所有现有组件都用 inline style + 样式常量）
- `--color-primary-soft` 什么时候用 vs `--color-accent-soft`——没规则，大致是：primary-soft 给"当前选中/进行中"，accent-soft 给"一般 chip 底"
- 加载态 fontSize 14 + textAlign center + color subtle（C-5 锁的）
