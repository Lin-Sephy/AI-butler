## 形象规格

### 风格路线：偏玩偶化（不是写实）

**比例：**
- 头身比 **1 : 2.5**（介于玩偶 1:2 与写实 1:3.5 之间）
- 眼睛占头部 **1/4 - 1/5**（比玩偶克制，比真实醒目）
- 身体**修长但曲线柔和**，不追求解剖学肌肉，也不做圆球

**识别锚点（不能丢）：**
- 黑圆眼 + 粉红鼻尖 + 内耳粉（**脸部三锚**）
- 胡须 **4-5 根细长**（细节感是"不幼稚"的关键）
- **蓬松黑尾尖**（不是点，是一撮）
- 粉色四足小垫

**守住的底线：**
- ❌ 不走玲娜贝儿式巨头
- ❌ 不走写实冷感纤瘦
- ❌ 不做二次元吉祥物
- ✅ 参考对标：Apple Journal / Headspace 吉祥物的比例与调性

## 优先级 & 打断逻辑

**优先级（高抢占低，one-shot 完成后回持续态）：**

```
8  思考中 (thinking)      — 可被用户打断
7  开心蹦跳 / 好奇探身 / 警觉 (one-shot)
5  歪头在听 (listening)
3  专注陪伴 / 偶尔抬头 (专注遮罩)
2  眨眼 / 基础待机
1  蜷睡 (sleeping，长时无操作默认)
```

**思考打断规则：**
- 用户在 API 未返回时发新消息 / 切页 / 刷新
- 思考泡泡 fade-out 0.15s，小白立即切回 idle
- API 正常返回时：泡泡淡出 + 按回复内容切下一个状态（listening / happy / curious）

**场景切换：**
- 聊天室 ↔ 专注遮罩 之间通过 `intro` 状态过渡
- 任务页 / 数据页 桌宠不出现

## 聊天页双 mode layout（2026-04-15 定）

聊天页不是单一 layout，是**两个 mode**根据用户行为自动切换。这套设计同时解决：小白完整展示 vs 消息列表抢空间、11 个状态用户看不全、聊天时小白被压成陪衬装饰、桌宠动作资产 ROI 这四个问题。

### Mode A · 闲玩

**默认进入聊天页时的形态。** 没有消息流，是小白的"主场展示厅"。

- 白鼬 **全身居中**展示，参考 `参考_手绘白鼬_3色极简.png` 风格
- 背景：复用全局雪地（雪白底 + 落雪 + 极淡针叶暗纹）
- 顶部：**右** ⚙️ 设置（左侧空，Mode A 没有"退出"概念）
- 底部：输入框（**可输入但只暂存，不发送就不切 mode**）
- 历史消息**完全不可见**（让 Mode A 是干净的陪伴空间）
- **点身体部位触发状态**（"逗白鼬"）：
  | 部位 | 触发状态 |
  |---|---|
  | 头部 | curious 好奇探身（一次性 1s） |
  | 肚子 | happy 开心蹦跳（0.6s） |
  | 尾巴 | 抖动 / 警觉 alert（如果在 sleeping 则触发 waking） |
  | 空白处 | 不响应（避免误触） |
- **20 分钟无互动**自动进 sleeping（已在状态机里）

**为什么点身体不做软按钮：** SVG 里给不同 `<g>` 加 `onclick` 比 HTML 按钮还简单，且"点小动物身体"比"按按钮"更有陪伴感、更不像游戏 UI。

### Mode B · 聊天

**用户发送第一条消息后切入。** 注意是"发送"不是"打字"——闲玩时心血来潮在输入框敲字也不会被强切走，按回车/点发送才转入对话。

- 白鼬变 **半身**，趴在聊天框上沿，参考 `直立观察.png`
- 背景：**与 Mode A 同一套雪地**（不换底，氛围连贯，"你还在同一个雪地里，只是白鼬姿态变了"）
- 顶部：**左** `<<` 退出闲玩；**右** ⊕（圆形里加号）新建对话 · ⚙️ 设置（加号紧邻设置左侧）
- 底部：输入框（同位置）
- 中间：消息流（用户/AI 气泡 + "记录/再聊聊"按钮 + 精力确认等内联交互）
- 历史**复现**（除非按 ⊕ 新建对话清空）
- 状态触发：listening（用户打字时）/ thinking（API 调用中头顶 3 点泡泡）/ happy（任务完成 / 用户赞美）/ curious（新话题 / 触发新印象）
- 半身演不出来的状态（跑动 / 蜷睡 / 完整 intro）只在 Mode A 或专注遮罩里出现，Mode B 的状态白名单就这 4 个

### Mode 切换触发

| 切换 | 触发条件 | 过渡 |
|---|---|---|
| A → B | 用户**发送**第一条消息 | `intro` 状态做过渡（"半身偷看-01.png" 0.8s），掩盖资产切换 |
| B → A | 用户点顶部 `<<` 退出键 | 同 `intro` 过渡 |
| B 内"新建对话" | 用户点顶部 ⊕ | 不切 mode，仅清空消息历史，回到空 Mode B 状态 |

**仿 AI 软件（ChatGPT/Claude）的"新建对话"模式**——用户认知负担低。

### 为什么这套方案对

- **白鼬全身展示和聊天滚动列表不打架**：闲玩时全身主场，聊天时主动让位半身
- **11 个状态用户能看全**：闲玩 mode 是主场展示厅，逗着玩就触发不同状态
- **聊天时小白不是陪衬装饰**：半身趴在聊天框上沿 ≈ "趴在你键盘旁看你打字"
- **桌宠动作三处复用**：闲玩展示 + 聊天半身 + 专注遮罩，资产 ROI 最高

## SVG 实现参考（Clawd 路线）

**要抄的结构模式**（在 `C:/Users/Administrator/Desktop/clawd-on-desk/src/state.js`，纯结构参考，不碰视觉资产）：

- **`STATE_PRIORITY` 优先级表** —— 高优先级抢占低优先级
- **`ONESHOT_STATES` 自动回落** —— 一次性状态完成后自动回持续态
- **`MIN_DISPLAY_MS` 最小展示时间** —— 防止状态瞬闪
- **`pendingTimer` 抢占排队** —— 高优先级 one-shot 插队时的排队机制
- **SVG 状态切换 = SVG 替换 + opacity fade 过渡**（0→1，0.2s ease-out）—— 掩盖资产边界，切换不突兀
- **每个状态一个 SVG 文件**，内部用 CSS `@keyframes` 做动画
- **身体部件保留 JS hook**（`#eyes-js`, `#body-js`）用于动态 transform

**要砍的（Electron 桌面端特有，Web 用不到）：**
- mini mode / 边缘吸附
- `BrowserWindow` / `setIgnoreMouseEvents` / 置顶窗口
- `ipcMain` ↔ preload bridge
- 进程检测 / focus terminal / 光标跨屏追踪

**可选（v2 先不做，桌宠打磨阶段再加）：**
- 光标追踪 —— 实现"专注中桌宠抬头看用户"（眼睛角度跟光标联动）
