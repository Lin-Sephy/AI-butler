# 设计哲学

## "使用感大于一切，没什么不舍的"

v1 的三阶段流水线架构是 AI 写的——教科书式正确，7 个 JSON 字段、四路径路由、三层降级方案、Pydantic 校验、few-shot 示例 6 个。

从 v2 开始是 Sephy 主导的。每一版都在砍上一版的东西，每次砍完都更好。不是因为上一版"错了"，是因为发现了更本质的问题。没有什么"舍不得"，设计迭代出更合适的选择与方案更重要，使用感大于一切，没什么不舍的。

## 为什么从"推任务"变成"朋友聊天"

产品的核心不是任务管理，是**让用户愿意留下来**。

逻辑链：
1. 用户信任 → 愿意聊下去 → 愿意留下来
2. 留下来 → AI 积累对用户的了解和印象
3. AI 了解用户 → 推荐变得精准 → 用户更信任
4. 这个循环一旦转起来，就是护城河

如果第一步就推任务，用户觉得这又是一个冷冰冰的效率工具，关掉，没有然后了。

所以架构从 v2 的"每轮评估要不要推任务"改成了 v4 的"先聊天，Python 在后面悄悄判断"。DS 不知道自己有推任务的职责，它只是在跟朋友聊天——这才是用户愿意留下来的原因。

**核心吸引点不是任务推荐，是 AI 对用户的了解与印象。** 任务管理只是了解之后的自然产物。

## 竞品为什么做不到这一点

- 效率工具（Motion/ClickUp）：开屏就是任务列表，没有信任建立的过程
- 心理健康（Woebot/Wysa）：有聊天但不管任务，功能价值弱
- 自我关怀（Finch）：有信任但没有 AI 聊天能力，无法深度了解用户

小白在中间：**先建立信任（聊天），再提供价值（任务），用了解深化信任（印象系统）。**
