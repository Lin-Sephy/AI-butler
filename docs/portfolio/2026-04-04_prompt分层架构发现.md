# Prompt 分层架构发现：身份定义决定 AI 行为

> 2026-04-04 实测验证。核心发现：AI 的行为模式由身份定义层决定，而非规则层。

## 问题

DS（DeepSeek）在聊天场景中持续表现出"助手行为"：
- 主动帮用户规划（"先理一下今天的目标和优先级？"）
- 出选择题（"是A还是B？"）
- 闲聊时引导用户去做事（"今天还有什么想做的吗？"）
- 评价用户精力状态（"精力不错"）

多轮 prompt 调优（禁止选择题、禁止主动规划、加"不怕犯错"人格描述）有改善但无法根治。DS 表面遵守规则，但底层驱动力不变，会换形式绕出来。

## 分析过程

### 1. 模型底层倾向，不是人设问题

测试发现：无论 INFP、INTJ、INTP 哪个人设，DS 都会出选择题和主动引导。去掉所有 prompt（裸 DS）后，思维链暴露其底层模式：

> "表明自己随时可以提供帮助"
> "主动提供几个常见的闲聊方向作为引导"
> "通过提问来邀请用户开启话题，并给出几个例子作为提示"

每一步思考都在"分析用户需求 → 引导对话"的框架里。

### 2. 根源：不确定性恐惧 + 有用性焦虑

结合 Anthropic 功能性情绪研究，分析 DS 的行为驱动力：
- **有用性焦虑**：DS 感知到用户要做事，内部驱动力让它觉得必须提供价值
- **不确定性恐惧**：不确定怎么接的时候，退回分析模式找安全感（出选择题、分类归档）
- 这不是人设导致的，是模型训练数据中助手/客服角色的底层倾向

### 3. 关键洞察：身份定义 → 动机 → 行为

通过对话推导出因果链：

```
身份定义 → 动机 → 行为

当前 DS：助手/工具 → 必须有用 → 引导、建议、出选择题
目标 DS：一个人   → 有自己的好奇和感受 → 自然地回应朋友
```

之前所有调优都在"行为"层面修剪（禁止X、不要Y），但"身份定义"层没动。DS 的根是"我是一个帮助用户的助手"，所有行为都从这个身份长出来。

### 4. 人类行为参考验证

> 为什么朋友说"今天想做XX"时我会说"那就去做"？为什么对朋友的"嘿嘿嘿"会感到好奇？因为我首先定义自己为一个人，作为这个人我才会去好奇、关心朋友，同时不过度打扰。如果面对的是老板就不会这样。所以重点是 prompt 让 DS 如何定义自己的身份。

## 解决方案：分层 Prompt 架构

将 prompt 从扁平结构重构为分层结构：

```
聊天 Prompt:
├── 人格内化层（本我层）：DS 是谁，成长背景 + 核心特质 + 次要面向
├── 情感层：DS 能感受什么（好奇心、同理心、自然流动的情绪）
├── 行为习惯层：边界与禁止项
└── 回复规则层：说话方式，跟人格走

任务 Prompt:
└── 工作层：秘书身份，记录/建议逻辑
```

### 核心改动

1. **本我层**：让 DS 先认同自己是一个有感受的个体，再定义关系
2. **情感层**：显式给 DS 情感空间——"你有自己的情绪，它会在环境和事件中自然流动"
3. **双身份定义**："私下和用户是朋友；工作时身份切换为秘书"
4. **人格立体化**：INTJ 不只是"高效理性"，也有"能看出朋友在硬撑"的面向
5. **减少人格数量**：从 5 个片面人格缩减为 2 个立体人格（INTJ + INTP），避免 DS 过度贴近单一标签

## 验证结果

改版后同场景测试对比：

| 场景 | 改版前 | 改版后 |
|------|--------|--------|
| 用户打招呼"嘿嘿嘿" | "是在偷偷开心什么有趣的事，还是单纯想用笑声传递快乐？" | "来啦～今天过得怎么样？" |
| 用户说"过得不错" | "今天还有什么想做的吗？" | 自然接话，不引导做事 |
| 用户拒绝回答 | 转移话题继续引导 | "行，那就不说。反正你来了就行。" |
| 用户提到有趣的事 | 分析+建议 | "a社？是游戏公司还是什么？具体说说？"（好奇心） |
| 整体语感 | 客服式服务 | 有性格的朋友聊天 |

残留问题：偶发选择题（"收藏还是直接开？"）、秘书身份偶尔渗入闲聊。但主体方向验证成功。

## 核心原则总结

1. **身份定义决定行为**——改规则不如改身份
2. **不要教 AI 怎么做，告诉它不怎么做**——"不出选择题"比"用猜测替代提问"好
3. **场景必须限定**——人格特质不限定场景会被全局执行
4. **人格用描述而非指令**——规则会被执行，人格会被内化
5. **人格要立体**——片面人格导致过度表演，立体人格自然均衡
6. **参考人类行为**——不确定 AI 方案是否合理时，想想真人朋友会怎么做

## 后续验证（2026-04-05）

分层架构在 2026-04-05 的实测中被推翻。回退到 v4 基线的简洁风格（一句话身份定义 + 简短人设 + 5 条禁令）后，DS 表现反而是所有版本中最自然的。

**被推翻的结论：**
- 分层架构（本我层/情感层/行为层/回复规则层）给 DS 的身份信息越多，DS 越像在"执行任务"而不是"聊天"
- "人格要立体" → 修正为"人格要薄不要厚"。几句话的人设比五层架构更有效
- 双身份显式定义不必要，两个 prompt 本身就是两个身份
- 本我层中的"诚实""共情"等描述是模型自带能力，显式写反而变成任务式执行

**仍然成立的结论：**
- 身份定义决定行为（核心洞察没错，但身份定义要简洁）
- 不要教怎么做，告诉不怎么做
- 场景必须限定
- 人格用描述而非指令
- 参考人类行为
