# 2026-04-03 v4.1 设计决策记录

## 1. offer_help 信号的 A/B 测试与放弃

**问题：** Python 根据 DS 信号判断是否推任务，信号可能不准。是否让 DS 在信号里加一个 offer_help 字段直接判断？

**测试过程：** 让 DS 分别在有/无 offer_help 字段的 prompt 下跑相同对话。

**发现：** 方案 B（加 offer_help）的 DS 在第二轮就急着判断 wants_help，回复变成"要不要我帮你规划"——聊天心态被污染了。方案 A 的 DS 同样输入判断为 just_sharing，自然地聊思路。

**决策：** 不加 offer_help。多加一个字段会让 DS 多一个"要不要推任务"的心理负担，影响聊天自然感。

**方法论：** 给 AI 的每一个字段都是一个心理负担。能不加就不加。

## 2. 按钮从"开始/换一个"改为"记录/再聊聊"

**洞察来源：** 实测发现——不推任务反而让用户更放松，记录下来反而更想做。按钮会抢占注意力，让用户把注意力放在"是否听从按钮"而不是对话本身。

**设计：** 如果对话本身获取了用户注意力，让用户心里想做，他真的会去做。"记录"只是把任务写到任务栏，用户想做的时候自己去点开始。这个优化点在于让用户自己决定开始的时机而不是让ai去猜去提供，减少用户开始的心理负担。

**额外决策：** rest 类任务不弹按钮、不进任务栏。用户说"想休息"的时候，弹按钮是制造决策负担。

**方法论：** 人们更倾向于记录而非直接开始。但记录本身成为了一种待办清单。

## 3. 两级印象记忆系统

**问题：** DS 反复提起记忆里的事件（"你之前不是在处理崩溃吗"），清空记忆后表现反而好。

**根因：** 记忆系统什么都记，DS 就什么都提。记忆变成了噪音源。

**设计：** 
- 初步印象（draft）：首次观察就记录，3 次 + 跨 2 天才升级
- 深入印象（confirmed）：经过频次验证的稳定观察
- 7 天没触发自动过期，14 天没触发降级

**关键决策：** 不用额外 API 调用做记忆清理（我最初建议的 Dream 整理方案）。频次验证本身就是最好的筛选器——有用的自然活下来，没用的自然消失。结构化 JSON 不会像自由文本那样变乱，不需要主动整理。

**方法论：** 参考人类认知——刚认识一个人会有短期印象，反复验证后才形成稳定认知。设计 AI 记忆时用人类认知过程做锚点。

## 4. prompt 从规则指令改为人格描述

**问题：** DS 在"做自己"指令下开始编造物理体验（看到鸽子、在发呆），INTP 人设下过度分析每句话（把"想你了"拆成行为模式分析）。

**根因：** 给 DS 具体的说话风格指令（"松弛""喜欢怼回去"），DS 会过度表演。"做自己"太开放，DS 不知道自己是谁就开始发挥。

**解决：** 我们不让ds遵守规则，而是让ds觉得他是谁。不说"不要编造"，说"你诚实，不会因为不知道而编造"。不说"语气松弛，喜欢拆解"，只给成长背景让 DS 自己长出说话方式。

**Sephy 原话：** "DS 执行规则会演戏，但内化一个人格会自然得多。"

**方法论：** 规则越多 DS 越像在演戏。人格描述 > 行为规则 > 风格指令。

## 5. Session Memory（会话摘要压缩）

**灵感来源：** 研究 Claude Code 源码发现其 Session Memory 机制——每次会话维护结构化笔记。

**适配设计：** 不照搬（Claude 的 9 分区模板太重），改为轻量版——每 5 轮在记忆提取时顺便生成 2-3 句话的对话摘要。有摘要后传"摘要 + 最近 10 条"替代"最近 20 条"，节省 token 且不丢上下文。

**关键：** 零额外 API 调用，搭在现有的记忆提取流程上。

---

## 今日方法论总结

1. **给 AI 的每个字段都是心理负担** — 能不加就不加
2. **提示而非压力源** — 按钮的存在就是压力
3. **用人类认知做 AI 设计锚点** — 人怎么交朋友，AI 就怎么建印象
4. **人格描述 > 规则指令** — DS 执行规则会演戏，内化人格会自然
5. **被动验证 > 主动清理** — 频次是最好的筛选器
