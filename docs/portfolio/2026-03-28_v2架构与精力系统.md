# 早期设计决策：精力系统、守门校验、意愿矩阵、模型选型

## 1. 精力系统的三级采集策略

**问题：** 大部分精力/心情管理 App 开屏就让用户填状态，用户烦了就不用了。

**设计：** 三级采集，能不问就不问：
- 静默继承（零成本）：今天没变化就用昨天的值
- 轻触确认（一句话）：DS 感知的精力跟系统值偏差 >= 2 档，弹一个快捷按钮确认
- 完整采集（2-3 个问题）：只有首次使用或大变化时才触发

**方法论：** 零成本是最好的成本。用户不需要"管理精力"，系统自己感知。

---

## 2. 守门校验：信任 AI 的创意，不信任 AI 的判断

**设计：** AI 推荐的任务必须过一层纯 Python 规则校验：
- 精力 1 档：只允许恢复动作
- 精力 2 档：禁止深度工作
- 精力 1-2 档：禁止需要判断力的任务

**关键：** 守门校验不调用 LLM，是纯确定性逻辑。AI 负责创意（想推荐什么），Python 负责安全（拦住不合理的）。

**方法论：** AI 和确定性代码各有擅长。感知和创意交给 AI，安全边界交给代码。不要让 AI 既当球员又当裁判。

## 3. 意愿×状态二维矩阵（v2，后演化为 v4 信号架构）

**v2 设计：** 把"用户意图"拆成两个独立维度：
- 意愿：want / resist / unclear
- 状态：ready / blocked
- 6 种组合（combo A-F），每种有明确应对策略

**价值：** 拆成二维后，策略自然浮现。比如 want + blocked（想做但卡住）→ 给极低门槛入口，resist + ready（不想干但还行）→ 先肯定已做的再建议恢复。

**演化：** v4 砍掉了让 DS 做 combo 判断，改为 DS 输出观察信号（activity_category、user_attitude、emotion 等），Python 根据信号组合决定触发规则。本质上是同样的二维思维，但判断权从 AI 移到了 Python，更可控。Python 同时看 attitude、精力档位、事件类型三个维度做触发决策。

**方法论：** 把模糊问题拆成独立维度，策略就自然浮现。判断权放在最可控的地方。

## 4. 从 GLM + DeepSeek 双模型到 DeepSeek 单模型

**v1 架构：** GLM 做意图判断 → 分类结果传给 DS → DS 生成回复。两次 API 调用。

**问题：**
- GLM API 响应时间过长，用户等很久
- GLM 做的意图判断是中间结果，DS 拿到的是二手信息而非用户原话
- 两次调用的延迟叠加，体验很差

**v2 决策：** 砍掉 GLM，让 DS 直接拿一手消息做意图判断 + 回复生成，一次调用完成。

**效果：** 响应速度提升，且 DS 直接看到用户原话，理解更准确。

**方法论：** 中间层能砍就砍。让 AI 拿到一手信息，比经过加工的二手信息效果好。延迟是用户体验的杀手。
