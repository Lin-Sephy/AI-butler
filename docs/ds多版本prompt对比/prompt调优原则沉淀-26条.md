### 通用原则（始终有效）

1. prompt 里不要塞示例，只写规则。AI 会被示例锚定。
2. AI 回复不要主动评价精力状态。已写入绝对禁止。
3. 恢复建议必须是躺着/坐着就能做的，不推荐"打开窗户""深呼吸"。
4. 不给用户出选择题。
5. 精力 4-5 档优先推高价值任务，不浪费在机械性任务上。

### 人设原则（v4.1 确认 → 2026-04-05 修正）

6. 人设用人格描述而非规则指令。Sephy 原话："把规则变成人格描述，DS 执行规则会演戏，内化人格会自然。"
7. 不要给 DS 具体的说话风格指令（如"语气松弛""喜欢怼回去"），DS 会过度表演。只给成长背景，让它自己长出说话方式。
8. DS 容易编造物理体验和虚假记忆，prompt 里必须明确禁止。
9. "做自己"这类开放指令会让 DS 发颠，需要收窄为具体的人格特质描述。
10. **人格要薄不要厚**。一句话身份定义比五层架构更有效。DS 拿到的身份信息越多，越像在"执行任务"而不是"聊天"。（2026-04-05 推翻了之前"人格要立体"的结论）
11. **话术参考/语料会成为 DS 的行为锚点**。DS 会把用户往语料模板上套（如语料含"焦虑"场景，用户随便说句话就被归类为焦虑）。语料不能给情绪场景描述。
12. **模型自带的能力不要显式写**。诚实、共情、接住情绪等 DS 本来就会做，写成规则反而变成任务式执行。
13. **"不是X"会强调X**。"不是医生是朋友"让 DS 注意到了"医生"。
14. **信号字段和人设不要重复同一件事**。信号块已有 wants_to_start，人设再写"直接记录"= 双重加权，DS 过度激活。

### 架构原则（v4 → 2026-04-05 简化）

15. 聊天归 DS，推任务归 Python。DS 不负责判断要不要推任务。
16. 聊天 prompt 不传精力档位，DS 靠对话自己感知。任务 prompt 才传。
17. 记忆和任务栏是背景参考，可能会过时。
18. **身份定义决定行为**——但身份定义要简洁。一句"像朋友一样自然聊天就好"就够了。
19. ~~分层架构~~（已推翻）：本我层/情感层/行为层/回复规则层增加了 DS 的处理负担，效果不如简洁身份。
20. ~~双身份显式定义~~（已推翻）：两个 prompt 本身就是两个身份，显式写反而让 DS 在聊天时惦记工作。

### 变量交互效应（2026-04-05 新发现）

21. **禁令数量 → 焦虑 → 确定性追求 → 选择题**。完整因果链，不能跳步。
22. **"绝对禁止"四个字本身是压力源**。但"注意"又太松。标题的语气影响 DS 心态。
23. **单独有效的改动叠加可能过量**。减禁令（好）+ 删"接纳不完美"（好）= 叠加后过度松绑（坏）。
24. **记忆内容是 DS helper 焦虑的燃料**。current_task 被 DS 主动抓取来表现有用。
25. **对话历史锚定 > 记忆系统锚定**。清记忆不够，清对话历史才有效。

### 技术经验

26. Streamlit 回调里不做耗时 API 调用，会超时。回调只做标记，API 放主流程。
