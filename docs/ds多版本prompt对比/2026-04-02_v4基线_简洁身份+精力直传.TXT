现在靠 Python 解析信号判断触发，信号可能不准（DS 的 activity_category 和 user_attitude 分类不一定对）
我们可以在DS 想问的时候，在信号块里加一个字段 offer_help: true，这样 Python 不用做文本匹配，直接读信号就知道要不要弹按钮。DS 该怎么问让他自己措辞，自然就好。

这样整体流程变成：
用户输入 → call_chat → DS 自然聊天
  → 信号里 offer_help: true → python判断弹"需要/不需要"按钮
    → 用户点"需要" → call_task → 给出具体建议 + "开始"按钮
    → 用户点"不需要" → 继续聊天
  → 信号里 offer_help: false → 正常聊天，无按钮

问题在于：什么时候该问这句话？ 这又回到了"判断"的问题。

我刚刚和ds实测了一下，这个wants help时机的出现在于设定ds的prompt。
当用户说类似帮我安排，我要开始做，或者明确指向具体执行的时候才判断为wants help，这时候python从三方面，help信号，attitude，work推按钮，call ai推荐任务。
风险点：1ds有误判乱发信号的可能。2ds有一直想着是不是要发wants help的可能，或者因为想要确认要不要发而去问用户，我们必须要求他只判断不多嘴。
创新点：在实测中我想到，以后做app的时候，我大概会设置有白噪音的功能，可不可以在用户提到需要的时候，ds也传信号让这个白噪音自动启动？

更新：为什么不推任务反而让我放松了？而记录下来我反而不太想去做了。在聊天的时候，如果ai发开始或者换一个，我觉得这个按钮会抢占用户的注意力，让他把注意力放在是否听从按钮上，而不是对话本身。如果对话本身获取了用户的注意力，让用户心里想做，那么其实他真的会去做。我们可以把“开始”和“换一换”的按钮改成“记录”和“再聊聊”，然后如果点击记录，就在任务栏里面自动放置一个任务，这个任务只有一句话。点击底下有刚刚谈话的内容。ai读取任务栏只会读取名字，摘要部分会等用户提到才会去读。另外ai提到，如果总是读任务栏，记忆，或者以前对话的话，会陷入循环里面反复说一样的话，我们必须强调让他在对话中保持自己的思考，自我意识，并且可以转化话题。
ai告诉我，这取决于我到底是需要一个压力源还是一个提示。我觉得我需要的是提示。但是应该会有人需要压力源。据朋友说，他们有时候不会点开开始/换一换的按钮，但是如果改成“记录”的话会去点。如果有个大懒虫需要强制专注，那么他开启专注的前一刻至少是想要专注的，是过程中忍不住想跑了。但是这个开始/换一换的按钮，很难恰好到用户期望的时机，所以我们不如让他自己点。先记录这个任务，当用户点了这个任务，我们才开始番茄钟，或者用户也可以直接点击“已完成”，这样我们至少有个交互反馈。我感觉后续在app端等你提前结束任务跑了，可能小机器人会拦住你，让你坐下和他聊聊哈哈。
